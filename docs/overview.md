# Обзор прототипа

Перенесено из старого README. Полное устройство панели и все оси — в [scenarios.md](scenarios.md).

## Что это

Vite + React + TypeScript, роутер — TanStack Router (файловый), стили — CSS дизайн-системы плюс Tailwind v4. Сценарий приложения живёт в хэше ссылки, поэтому любую комбинацию можно скинуть команде одним URL.

Прежняя однофайловая версия из `archive/index.html` удалена: движок переехал в `src/legacy/prototype.js` и с тех пор разошёлся с ней на десятки правок по макетам. Если понадобится — она осталась в истории: `git show 764df1b:archive/index.html > archive.html`.

## Структура

```
src/
  main.tsx              точка входа
  routes/               маршруты: __root.tsx (каркас), index.tsx (Главная), $route.tsx (разделы)
  state/store.tsx       состояние сценария и интерфейса, обработка кликов, синхронизация с хэшем
  components/           каркас: Sidebar, Header, Coinbar, Footer, Modal, ScenarioPanel, Toasts
  legacy/prototype.js   движок из архива: данные, иконки, экраны, модалки — переезжает в TSX по частям
  styles/               app.css (дизайн-система), react.css, index.css
```

## Сценарии

Кнопка **⚙ Сценарии** в правом нижнем углу (или клавиша `S`) открывает панель переключателей. Основные оси:

| Ось                | Значения                                        |
| ------------------ | ----------------------------------------------- |
| Монета             | BTC / LTC + DOGE                                |
| Наполнение данными | Норма / Пусто / Мало записей / Большие значения |
| Здоровье парка     | Всё живо / Деградация / Авария                  |
| Роль               | Владелец / Наблюдатель                          |
| Уровень рефералки  | 5% / 10% / 15% / 20% / 25%                      |
| Верификация        | Не пройдена / На проверке / Пройдена            |
| Уведомления        | 12 новых / 2 новых / Нет                        |
| Аккаунт            | Основной / Суб-аккаунт                          |

Оси задаются в объекте `AXES` — новый сценарий добавляется одной строкой. Полный список — в [scenarios.md](scenarios.md#оси).

Отдельная вкладка «Стиль» — про внешний вид: шрифт, акцентный цвет, скругления, отступы, набор иконок и тонкая настройка токенов. Получившееся оформление сохраняется темой, сравнивается с дизайн-системой одной кнопкой и выгружается в JSON формата Design Tokens — его понимают плагины импорта переменных в Figma.

## Дизайн

Токены, размеры контролов и типографика сняты с прод-сборки дизайн-системы и живут в коде. Шрифт Gilroy (5 начертаний, woff2 с прода) лежит в `public/fonts` и подключается из `src/styles/app.css`, поэтому прототип рендерится тем же шрифтом, что и продукт. Иконки — Solar Bold Duotone из макетов дизайн-системы (подробности — в [icons.md](icons.md)). Есть тёмная тема — переключатель в хедере. Список макетов — в [context.md](context.md).

## Чат в панели

Пятая вкладка панели — чат: он включает состояния словами («авария на парке», «открой выплаты») и меняет оформление («фон темнее», «скругления 4»). Разбор запроса локальный, в `src/chat.ts`, — прототип работает без сети и без ключей.

За чатом можно поставить настоящую модель. Ключ от API на статической странице держать негде, поэтому он живёт на маленьком прокси — исходник и инструкция в [worker/README.md](../worker/README.md). Прототипу достаточно двух переменных сборки:

```bash
VITE_AI_URL=https://prototype-chat.<аккаунт>.workers.dev VITE_AI_TOKEN=<щеколда> npm run build
```

Чат умеет и то, чего в прототипе нет: «новый раздел Бонусы» собирает черновик из блоков дизайн-системы — с пунктом в сайдбаре, пометкой «черновик» и своей ссылкой. Это песочница поверх прототипа, а не раздел продукта: с макетами он не сверялся.

Пока переменных нет, чат разбирает запросы сам. Ответ модели проверяется по белым спискам (`src/ai.ts`): применяются только известные оси с их значениями, токены темы в диапазоне, существующие экраны и окна. Оформление — только если о нём попросили. Если прокси молчит или ответил не тем, включается тот же локальный разбор, и чат об этом говорит.
