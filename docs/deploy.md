# Публикация и пароль

Перенесено из старого README.

## Cloudflare Pages

web-prototype-pool раздаётся с Cloudflare Pages. Доступ команды настраивается через Cloudflare Access по инструкции ниже. Сборка уезжает из терминала, а не с GitHub: Cloudflare Pages выбран, когда репозиторий был приватным, — GitHub Pages на бесплатном плане из приватного репозитория не собираются.

Войди в Cloudflare:

```bash
npx wrangler login
```

Собери и залей:

```bash
npm run deploy
```

Второй шаг собирает проект и заливает `dist/` в проект `web-prototype-pool`. Имя проекта и папка сборки — в `wrangler.jsonc`, отдельных флагов команде не нужно.

Проект уже создан, так что первый шаг из истории повторять не нужно. Если когда-нибудь придётся создавать заново — только с `--force`:

```bash
npx wrangler pages project create web-prototype-pool --production-branch main --force
```

Без флага Wrangler отправляет проект на новую платформу Pages (она теперь часть Workers), а та считает правило `/* /index.html 200` в `_redirects` бесконечным циклом и отказывает. Классический Pages его принимает — и у него же есть встроенная интеграция с Access.

Фолбэк на `index.html` лежит в `public/_redirects` и попадает в сборку сам. База — корень домена, поэтому `BASE_PATH` задавать не нужно.

## Кто внутрь: Cloudflare Access

Пароль в `src/gate.ts` — щеколда: проверка идёт в браузере, а хэш лежит в бандле, так что обойти её может любой, кто откроет исходник страницы. Настоящая дверь ставится в Cloudflare и стоит ноль до 50 человек:

1. **Zero Trust → Access → Applications → Add an application → Self-hosted**;
2. домен — адрес проекта на `pages.dev`;
3. политика **Allow** с правилом _Emails_ и списком почт команды (или _Emails ending in_ — весь домен компании);
4. способ входа — **One-time PIN**: код приходит на почту, заводить ничего не нужно.

После этого страница открывается только своим, а пароль в прототипе можно оставить как есть или убрать — он больше ничего не решает.

## Другие хостинги

Прототип — статический SPA, `npm run build` кладёт сборку в `dist/`, и раздать её может кто угодно при двух условиях:

- **фолбэк на `index.html`** — иначе прямая ссылка на раздел даёт 404;
- **база** — пути к картинкам собираются от `import.meta.env.BASE_URL` (константа `A` в движке); для раздачи из подпапки собирай с `BASE_PATH=/подпапка/`.

Настройки для Vercel лежат в `vercel.json` (`vercel login`, затем `vercel --prod`). Workflow для GitHub Pages удалён вместе с переездом. Понадобится — он в истории: `git show f08e383:.github/workflows/pages.yml`.

Сценарий живёт в хэше ссылки, поэтому ссылки со сценариями работают на любом хостинге.

## Поисковики

Прототип не должен попадать в поиск: мета-тег `robots` в `index.html`, `public/robots.txt` и заголовок `X-Robots-Tag` в `public/_headers`. Главный — заголовок: robots.txt закрывает обход, но не индексацию по внешней ссылке.

## Пароль на вход

Прототип закрыт паролем: при первом открытии показывается экран «Войти в прототип», дальше ключ лежит в `localStorage` и на этом устройстве больше не спрашивается.

Хэша пароля в репозитории нет. Он подставляется при сборке из переменной `VITE_GATE_HASH`, а живёт она в `.env.local` — файл в `.gitignore`. Переменной нет (свежий клон, чужая сборка) — щеколды нет, прототип открывается сразу; так сборка не запирается наглухо неизвестным паролем.

Задай или смени пароль:

```bash
npm run gate
```

Скрипт спросит пароль, посчитает SHA-256 и перепишет `.env.local`. Ввод скрыт: вместо символов печатаются точки. Сам пароль никуда не пишется — ни в файл, ни в историю команд. Дальше `npm run deploy`; все, кто уже входил, спросятся заново.

Если скрытый ввод в терминале не набирается, есть два обхода:

```
npm run gate -- --show          пароль виден на экране
echo 'пароль' | npm run gate    без терминала вообще
```

**Это щеколда, а не защита.** Проверка идёт в браузере: хэш всё равно попадает в собранную страницу, иначе браузеру нечем сверять. Кто откроет исходник страницы — обойдёт её за минуту. Настоящая дверь — Cloudflare Access перед раздачей, он описан выше.
