# Promminer Pool — прототип

Прототип личного кабинета майнинг-пула. Vite + React + TypeScript, роутер — TanStack Router
(файловый), стили — CSS дизайн-системы (`src/styles/app.css`) плюс Tailwind v4 для нового кода.
Контекст, ссылки на макеты и дизайн-токены — в `docs/context.md`, план — в `docs/roadmap.md`.

Запуск: `npm run dev` → http://localhost:5173. Проверка сборки: `npm run build`.
Три проверки перед коммитом: `npm run sweep` — рендерит все экраны × модалки ×
значения осей (сейчас 29 110 комбинаций) и падает на первой ошибке;
`npm run panel` — так же прогоняет панель сценариев (она на React, поэтому
собирается через `vite.ssrLoadModule`, тестового стека не нужно);
`npm run audit` — ищет `data-*` без обработчика, оси без влияния, экраны
и модалки без точки входа, пиксели мимо токенов, расхождения осей и связок.
Итоги сквозной проверки — в `docs/audit-final.md`, разбор панели —
в `docs/audit-scenarios.md`.

Эталон внешнего вида — макеты Figma и прод: однофайловый прототип, с которого всё
начиналось, удалён (лежит в истории, `git show 764df1b:archive/index.html`).

## Структура

```
src/
  main.tsx              точка входа, RouterProvider
  routes/               файловые маршруты: __root.tsx (каркас), index.tsx (Главная), $route.tsx (разделы)
  state/store.tsx       состояние (S — сценарий, U — интерфейс), делегированный обработчик кликов, хэш-ссылка
  components/           каркас в React: Sidebar, Header, Coinbar, Footer, Modal, ScenarioPanel, Toasts
  legacy/prototype.js   движок из архива: данные, иконки, общие блоки, экраны, модалки (+ .d.ts)
  styles/               app.css (перенесён из архива), react.css, index.css (сборка + Tailwind)
```

## Правила работы

- Экраны переезжают из `legacy/prototype.js` в TSX **по одному**: новый компонент в `src/screens/`,
  старая строковая функция удаляется из `V`. Пока экран не переехал, его рендерит `components/Screen.tsx`.
- Взаимодействие размечается `data-*` атрибутами и обрабатывается одним делегированным
  обработчиком в `state/store.tsx` — так React-компоненты и строковые экраны живут вместе.
- Внешний вид сверять с макетами Figma и дизайн-системой (список файлов — в `docs/context.md`);
  макеты бывают на разных страницах одного файла.
- Иконки — выгружены из дизайн-системы (страница UI icons, стиль Bold Duotone)
  в `src/legacy/icons.js`; они перекрывают объект `I` в движке. Руками не рисовать
  и файл не править — способ выгрузки и подводные камни в `docs/icons.md`.
  Четыре альтернативных набора (ось «Иконки») собраны с Iconify скриптом
  `scripts/icon-packs.mjs` в `src/legacy/icon-packs/` — тоже только скриптом.
  В TSX вставлять через `<Ico html={I.name} />`.
- Новый сценарий добавляется осью в объект `AXES` (плюс значение по умолчанию
  в `DEF` и ключ в `Scenario` в `state/types.ts`); сценарий сериализуется в хэш
  ссылки. Ось обязана на что-то влиять — `npm run audit` ловит мёртвые —
  и обязана опираться на кадр в макетах: выдумывать состояния нельзя.
  Придуманные раньше перечислены в `AX_OWN` и помечены в панели чипом «своё».
  Исключение — шесть осей оформления (`AX_STYLE`: шрифт, акцент, скругления,
  отступы, иконки и тонкая настройка): это не состояния продукта, а эксперимент
  с внешним видом, у них своя вкладка «Стиль» и в списке осей их нет.
  Устройство панели, обучение (`src/tour.ts`) и полный список осей —
  в `docs/scenarios.md`.
- Тонкая настройка (`src/theme.ts`) — патч токенов поверх дизайн-системы:
  белый список из 16 ключей, значения в диапазоне, запись в ссылку строкой
  `t1_bg-f5f5f5`. Набирается фразами в чате панели («фон темнее»,
  «скругления 4», «крупнее текст»). Свободного CSS в прототипе нет и
  не заводить: ссылка не должна нести чужой код. Числа дизайн-системы
  продублированы в `BASE`/`BASE_DARK` — `npm run audit` (раздел G) сверяет
  их с `app.css`, чтобы они не разошлись.
- Взаимоисключающий выбор (вкладки, периоды, тип лица, монета) — только компоненты
  дизайн-системы: `seg()` (Segment Control) или `segLine()` (Segment Control Line,
  модификаторы `fill`, `inv` для цветной подложки). Чипы — только для фильтров
  и множественного выбора.
- Хедер `.top` зафиксирован при скролле (`position:sticky`), а панель хедера, карточки
  и футер делят одни левую и правую границы: горизонтальные отступы живут на `.main`,
  у `.page` их нет. По макету контент прижат к сайдбару, а справа отступ 16
  (`.main{padding:0 16px 0 0}`).
- Шаг между блоками страницы — **16**, его раздаёт `.page{gap:16px}`. Распорки
  вида `<div style="height:12px">` и `margin-bottom` у блоков верхнего уровня
  не нужны: они складываются с зазором и дают 28–44 вместо 16.
- Картинку из макета выгружать без подложки кадра: белый фон в тёмной теме
  виден прямоугольником. Проверить — `node scripts/unmatte.mjs --check public/*.png`,
  почистить — тот же скрипт без `--check` (подробности в `docs/audit-assets.md`).
- Пути к картинкам в движке собираются от константы `A`
  (`import.meta.env.BASE_URL`), а не пишутся от корня: прототип может
  раздаваться из подпапки (GitHub Pages). Новую картинку вставлять как
  `src="${A}name.png"`, иначе она отвалится на Pages. Подробности
  о публикации — в README.
- Вход в прототип закрыт паролем (`src/gate.ts`, экран `components/Gate.tsx`).
  Это щеколда от случайного посетителя, а не защита: проверка идёт в браузере.
  Смена пароля — `npm run gate`, подробности в README.
- Прод для сверки данных и формулировок: https://pool.promminer.ru/
- Список страниц Figma с их `node-id` — в `docs/figma-pages.md`. Получить заново:
  `use_figma` со скриптом `return figma.root.children.map(p=>({id:p.id,name:p.name}))`
  (`get_metadata` без `nodeId` отдаёт только первый элемент верхнего уровня).
- В панели страниц Figma ничего не перетаскивать — порядок страниц в живом файле пользователя.
